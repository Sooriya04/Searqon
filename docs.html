Searqon

Self-hosted web search and scraping API for AI agents, RAG pipelines, and developer tooling. Single Go binary. No external services required.

REST API

JSON in, JSON out. Runs on :7493. No SDK needed — works with curl, any HTTP client, or your agent's native fetch.

MCP & UTCP

Native Model Context Protocol server and Universal Tool Calling Protocol support for direct agent integration.

4-Tier Anti-Bot

Automatic escalation from plain HTTP to residential proxy. Zero configuration — Searqon handles fallback internally.

Embedded Storage

SQLite WAL mode by default, PostgreSQL + pgvector for scale. Redis optional L1 cache. No external DB required to run.

How it works

A single POST to /search or /pipeline triggers the full ingestion chain:

  1. Discovery — query routes to configured search providers (SearXNG, DDG, Wikipedia, Arxiv)
  2. Deduplication — results merged by content hash and ranked with reciprocal rank fusion + BM25
  3. Scraping — each URL fetched through the 4-tier escalation ladder
  4. Extraction — HTML stripped to clean Markdown; ads, navbars, tracking removed
  5. Chunking — optional: splits into 500-token windows with heading breadcrumbs and overlap
  6. Caching — results persisted with content_hash and fetched_at for citation provenance

Quick Start

The fastest path is Docker. Searqon ships as a ~8 MB scratch image with no runtime dependencies.

Docker (recommended)

docker run -d \
  -p 7493:7493 \
  -v $(pwd)/data:/app/data \
  sooriya04/searqon:latest

Docker Compose

curl -O https://raw.githubusercontent.com/Sooriya04/Searqon/main/docker-compose.yml
docker compose up -d

Build from source

git clone https://github.com/Sooriya04/Searqon.git
cd Searqon/src
go build -o searqon ./...
./searqon

Verify

curl http://localhost:7493/health
Default port

Searqon binds to 0.0.0.0:7493 by default. Change with SERVER_PORT env var or in config/settings.yml.

Storage Backends

Searqon uses SQLite (WAL mode) by default. No configuration needed — the database is created automatically at data/searqon.db.

SQLite (default)

# No config needed. Data directory is mounted via -v $(pwd)/data:/app/data
# WAL mode enabled, BM25 FTS index built on first run

PostgreSQL + pgvector

# settings.yml
database:
  driver: postgres
  dsn: "postgres://user:pass@localhost:5432/searqon?sslmode=disable"

pgvector enables approximate nearest-neighbor search over cached page embeddings. Requires the vector extension installed in Postgres.

Redis (optional L1 cache)

cache:
  redis_url: "redis://localhost:6379"
  ttl: 3600  # seconds

When configured, Redis sits in front of the SQLite/PG cache. Cache misses fall through to the DB tier.

UTCP — Universal Tool Calling Protocol

Searqon implements UTCP, allowing AI agents to invoke search and scraping as structured tool calls without writing custom glue code.

To discover available tools, fetch the UTCP manifest:

curl http://localhost:7493/utcp/manifest

The manifest describes all tools with JSON Schema parameter definitions. Agents that support UTCP can auto-configure from this endpoint.

Code-mode

UTCP also supports a code-mode variant where the agent generates a call expression from the schema rather than calling the HTTP endpoint directly. See the GitHub README for details.

MCP — Model Context Protocol

Searqon runs a native MCP server, exposing its capabilities as MCP tools. Compatible with Claude Desktop, Continue, and any MCP host.

stdio transport (Claude Desktop)

Add to your claude_desktop_config.json:

{
  "mcpServers": {
    "searqon": {
      "command": "docker",
      "args": [
        "run", "--rm", "-i",
        "-v", "/path/to/data:/app/data",
        "sooriya04/searqon:latest",
        "--mcp-stdio"
      ]
    }
  }
}

HTTP transport

# MCP over HTTP (SSE transport)
curl http://localhost:7493/mcp/sse

Exposed MCP tools mirror the REST endpoints: search, scrape, scrape_chunked, crawl, map, and pipeline.

SSE Streaming

Progressive search results over Server-Sent Events. No polling — connect once and receive events as they emit.

curl -N "http://localhost:7493/search/stream?query=golang+vector+databases&limit=5"

Event types emitted in order:

EventPayload
discoverySearch results from providers (title, url, snippet)
scrapeScraped Markdown content per URL as it completes
synthesisFinal ranked and deduplicated result set
errorPer-URL scrape failure with tier and reason
doneStream complete signal

Each event is a JSON object: data: {"event": "scrape", "url": "...", "markdown": "..."}\n\n

Core REST Endpoints

All endpoints accept and return application/json. Base URL defaults to http://localhost:7493.

MethodPathDescription
POST/searchMulti-engine web search with optional scraping and RRF ranking

Scraping & Chunking

POST /scrape

{
  "url": "https://example.com/article",
  "format": "markdown",           // "markdown" | "html" | "text"
  "stealth_level": "auto",        // "auto" | "fast" | "stealth" | "headless"
  "timeout_ms": 10000
}

Response includes markdown, word_count, content_hash, fetched_at, bot_detected, and escalation_tier.

POST /scrape/chunked

{
  "url": "https://arxiv.org/abs/2312.00752",
  "chunk_size": 500,              // tokens per chunk
  "chunk_overlap": 50,            // overlap tokens
  "include_bm25": true
}

Returns an array of chunks, each with index, token_count, bm25_score, heading_breadcrumb, and content. Ready for direct vector DB ingestion.

POST /pipeline

{
  "query": "attention is all you need",
  "limit": 5,
  "scrape": true,
  "chunk": true,
  "chunk_size": 500
}

The pipeline endpoint is the recommended entry point for RAG workflows. It runs the full chain and returns ranked, chunked results in one response.

settings.yml

Searqon reads config/settings.yml at startup. All fields have environment variable overrides.

server:
  port: 7493
  host: "0.0.0.0"

database:
  driver: sqlite           # sqlite | postgres
  path: "data/searqon.db"  # sqlite only
  # dsn: "postgres://..."  # postgres

cache:
  ttl: 3600                # cache TTL in seconds
  # redis_url: "redis://localhost:6379"

search:
  default_provider: searxng
  searxng_url: "http://localhost:8080"
  providers:
    - searxng
    - duckduckgo
    - wikipedia
    - arxiv

scraper:
  timeout_ms: 10000
  max_concurrency: 8
  default_tier: auto       # auto | fast | stealth | headless

rate_limiter:
  requests_per_minute: 60
  burst: 10

Anti-Bot Escalation Tiers

Each scrape request starts at Tier 1. If blocked (detected via status codes, challenge pages, or redirect patterns), Searqon retries at the next tier automatically.

TierMethodTypical LatencyTriggers for escalation
T1 Direct HTTP (Go net/http) 50–200 ms 403, bot detection signature in body
T2 Spoofed browser headers + TLS fingerprint 200–600 ms Cloudflare 1s challenge, CAPTCHA page
T3 Lightpanda / Camoufox headless browser via CDP 1–4 s JS-rendered challenge, Cloudflare 5s
T4 Residential proxy pool rotation 2–8 s IP-rate-limited, geo-blocked targets

The escalation_tier field in every response tells you which tier ultimately succeeded. Use stealth_level: "fast" to cap at T2, or "headless" to start at T3.

SSRF protection

Scrape requests to private IP ranges (127.x, 10.x, 192.168.x, 169.254.x) are blocked by default. Set SEARQON_ALLOW_PRIVATE=1 to disable in trusted environments.
